# 常见问题与注意事项

本章列出了在使用 `bit7z-rust` 时的常见问题、限制以及最佳实践。

## 1. 性能优化

- **库重用**: `BitLibrary` 在加载时会产生较大的开销，建议在应用程序的生命周期内重用同一个 `BitLibrary` 实例。
- **固实压缩 (Solid)**: 对于 7z 格式，开启固实压缩 (`solid(true)`) 会显著提高压缩率，但会降低解压单个文件的速度。
- **线程安全**: 7-Zip 的原生接口本身支持多线程。在 Rust 中，建议为每个并发操作创建一个新的 `BitCompressor` 或 `BitExtractor` 实例，但共享同一个 `BitLibrary`。

## 2. 已知限制

- **路径编码**: 7-Zip 内部主要使用 UTF-16 处理 Windows 路径。在 Linux 上，路径编码取决于系统的 Locale 配置。
- **格式支持**: 并非所有格式都支持所有功能。例如，GZIP 仅支持单个文件，ZIP 不支持某些高级加密方式。
- **平台差异**: 7-Zip 的共享库（`7z.dll` vs `7z.so`）在不同平台上的行为可能略有差异，尤其是在处理符号链接和文件权限时。

## 3. 常见陷阱 (FAQ)

### 为什么我在 Linux 上无法加载 `7z.so`？
确保您已安装 `p7zip` 或 `7zip` 软件包。在某些发行版中，`7z.so` 位于 `/usr/lib/7zip/` 下，您可能需要手动设置 `BIT7Z_LIBRARY_PATH`。

### 为什么压缩 ZIP 时只能包含一个文件？
检查您是否错误地使用了 `GZip` 格式。如果是 `Zip` 格式且仍然只能压缩一个文件，请确保您没有在同一个 `compress` 调用中混用目录和文件（尽管库尝试处理这种情况）。

### 解压受密码保护的 RAR5 存档时出错？
请确保 7-Zip 库的版本足够新。RAR5 格式需要较新版本的 7-Zip 核心支持。

## 4. 最佳实践

- **错误捕获**: 始终检查 `Result` 并处理 `Bit7zError`。
- **路径安全**: 解压时请务必验证输出路径，避免恶意存档利用“路径遍历”漏洞覆盖系统敏感文件。`bit7z-rust` 包含基本的路径检查，但额外的业务验证总是有益的。
- **资源清理**: 及时释放 `BitLibrary`，尤其是在不需要再执行任何 7z 操作时。
